# Native PDF Smoke Check

This example runs the production PDF module in an isolated, hidden Tauri runtime.
It does not register production IPC or open Reader sessions. Its application identifier
is `com.reader.pdf-smoke`, separate from Reader's profile.

Build on Windows/MSVC:

```powershell
cargo build --manifest-path src-tauri/Cargo.toml --example pdf-export-smoke --target-dir target
```

Run with a self-contained HTML fixture generated by the export-preview E2E test.
Use an absolute output path. The default fixture settings are A4, 20mm, portrait
and page numbers enabled:

```powershell
.\target\debug\examples\pdf-export-smoke.exe INPUT.html D:/qa/standard.pdf standard
.\target\debug\examples\pdf-export-smoke.exe INPUT.html D:/qa/bookmarks.pdf bookmarks
.\target\debug\examples\pdf-export-smoke.exe LANDSCAPE.html D:/qa/landscape.pdf standard Letter 15 landscape
```

The paper, orientation and margin arguments must match the fixture's print CSS.
The output directory must already exist. A JSON result is written next to the PDF,
including failures without a console. Each invocation exits by itself. Page numbers
and bookmarks require WebView2 131 or newer; bookmarks are an optional experimental
DevTools protocol path, while standard export keeps the PrintToPdf interface.

`pdf-smoke.manifest` is embedded only into Cargo examples on Windows/MSVC because
the examples do not otherwise receive the main application's Common Controls v6
resource. It does not change production application privileges or manifests.
